# Coverage

This table describes what each check reads and where its limits are. It does not measure
real-world spyware detection rates or false-positive rates.

Run `--describe` for the individual check catalogue. Each scan's report lists the checks
that actually ran and the gaps encountered on that input.

| Check family | Reads | Limits |
|---|---|---|
| Chromium browsers and desktop apps | History, cookies, favicons, site storage, connection records, HSTS, download URL chains; raw app caches in full mode | Open/locked files, deleted data, schema changes; download hosts are attempted/contacted according to status and received bytes; neither proves execution. |
| Firefox | History, cookies, favicons, cache, text and binary HSTS stores | Partition metadata is not treated as the contacted host. |
| File fingerprints | Platform-specific user, application and temporary roots; Windows candidate extensions; Linux/macOS also extensionless/executable files, native libraries and scripts; all extensions in full/targeted mode | Exact known hashes only; 120 MiB per file; inaccessible paths. Full mode does not cover all drives or accounts. |
| Windows host and existing traces | DNS, COM, download origins, Win+R, Defender, PowerShell event logs, ShimCache and PCA | Logging may be disabled; records expire. ShimCache is presence evidence, not execution proof. |
| Added Windows records | PSReadLine, Explorer TypedPaths, Run/RunOnce, services, Startup files including supported `.lnk` metadata, and task actions; opt-in Sysmon/Security events | Rights and logging affect coverage. BAM and SRUM remain unsupported. Saved input and arbitrary Startup text remain references; recognized batch commands, Internet Shortcut URLs and literal shell-link launch metadata are persistence configuration. Shortcut IDLists, unfamiliar blocks/flags, ambiguous ANSI encodings and expansions remain gaps. Targets are never accessed or resolved. Other unknown formats and unsupported batch syntax are gaps. |
| Windows Prefetch and Amcache | Supported SCCA Prefetch layouts and allocated Amcache hive records; Windows live locations or explicitly selected copies on any OS | Prefetch executable-name evidence is `execution-record`, not full-path or content identification; metric paths remain references. Amcache is `inventory-record`, never execution proof or proof of current presence. Compressed Prefetch requires Windows; dirty hives need unsupported transaction-log replay. Locked files, unsupported layouts and exhausted bounds are gaps. |
| Linux startup configuration | Standard user/system autostart `.desktop` files, immediate systemd `.service` files and readable cron configuration | Unit/cron text and network strings are references. Only supported unconditional desktop executable paths can be configured evidence. No activation/override resolution, unit drop-ins, cron scripts, shell profiles or journal analysis. Other users' homes are outside scope. |
| macOS startup configuration | Standard user/system LaunchAgent and LaunchDaemon XML/binary property lists; literal Program/ProgramArguments | Exact executable-path configuration does not establish activation or execution. No managed login-item, unified-log or memory coverage. Unsupported or unreadable files are gaps. |
| Guided Android acquisition | Pinned official AndroidQF download, owner consent, local ZIP extraction, optional public age recipients | External collector changes device state. Windows collector unsigned; SHA-256 is publisher integrity, not an independent audit. Encrypted archives need separate decryption. |
| AndroidQF folders | Apps, JSON and legacy text process inventories, settings, files, logs, crashes, install history and SMS backup | Collection permissions and Android versions limit artifacts. JSON processes require positive integer `pid` and `command_line` string arrays; only the first command names the app. Archives must be extracted locally first. Encrypted SMS needs the password. Legacy password encodings may be unsupported. |
| Android intrusion logs | Decrypted newline-JSON `.txt` exports and supported ZIP members: DNS events, TCP connection attempts and process-start security events | Logging may be disabled or absent. DNS is `dns-record`; connection attempts and supported process records are `device-log`, not successful-contact evidence. Unknown events/schemas and encrypted input remain gaps. No live collection or decryption. |
| iPhone local evidence — experimental | Local backups, independently encrypted artifacts/WALs, extracted filesystems and selected sysdiagnose TAR/directory artifacts; messages, profiles, browser/process records, metadata and diagnostics described in [IPHONE.md](IPHONE.md) | Unsupported schemas/encoded-message variants, damaged WALs, encrypted root-manifest WALs and unavailable protection classes are gaps. No live/cloud acquisition, arbitrary deleted-record recovery or unified-log decoding. Source hashes identify bytes read, not device authenticity. |
| Context and related records | Publisher assertions, validity dates, withdrawal labels and matching records across artifacts | Publisher labels do not prove independent corroboration. A validity period is not necessarily a campaign period. Related records do not establish causation. |
| Report inspection and saving | Completed findings, references, gaps and fixed advice; readable report, full JSON and minimal sharing summary | No additional detection occurs in the menu. Quitting before a scan returns `4`, not a clean verdict. |
| Private evidence handoff | Full reports, effective indicator fingerprints and explicitly selected local files in a ZIP with an integrity manifest | ZIP is unencrypted and never uploaded. Up to 128 files, 64 MiB each, 256 MiB total payload including reports. Files are copied at export time, not retained scan snapshots; hashes do not prove original authenticity or infection. |
| Optional file patterns | The separately documented Candiru rules | Experimental; no memory scan or automatic dependency installation. |
